# NNTC Schedule 3.1.0-alpha.8.1 — отчёт об интеграции

**За основу взят фактически присланный проект:** `Projects 3.1.0-alpha2.zip`.
**Эталон технической ветки:** `NNTCSchedule_3.1.0-alpha.8_source.zip`.

## Что найдено

- В исходнике `ScheduleRouteUi.kt` отсутствовали импорт `ExperimentalMaterial3Api` и `@OptIn`, необходимые для использования `ModalBottomSheet`.
- После объединения дизайна с более ранней alpha.7 база `GroupScheduleDatabase` оказалась снова версии 1: были потеряны `GroupSubgroupEntity`, её DAO-методы и миграция Room 1 → 2.
- Код `ScheduleRepository` снова обновлял каталог **после** успешной обработки контрольной группы, хотя alpha.8 уже исправляла эту зависимость.
- `MainActivity` и обычные карточки расписания потеряли отображение отдельных подгрупп.
- Номер версии и внутренняя история изменений откатились на alpha.7.

## Что исправлено

- Устранена причина ошибки API Material 3 в `ScheduleRouteUi`.
- Сохранены визуальные правки нового экрана «Маршрут» (даты, станции, конечная точка маршрута, меню разработчика).
- Для «Маршрута» добавлен подробный показ двух подгрупп в карточке деталей — без склейки преподавателей/кабинетов.
- Восстановлены все изменения базы/парсера/обновления из alpha.8 и показ подгрупп в обычном интерфейсе.
- Номер версии согласован: `3.1.0-alpha.8.1`, versionCode 29. Изменения вошли в `Changelog.kt`.
- Созданы проверяемые SHA-256 патчи и утилита применения, которая останавливается при несовпадении версии файла.

## Что проверено в рабочей среде

- Чистый JVM-компилятор успешно собрал автономные классы `GroupCatalog`, `ExperimentalGroupTableParser`, `GroupSubgroupParser`, `GroupScheduleDiff`, `ScheduleDayStrip` вместе с проверочной моделью данных.
- 10 контрольных сценариев пройдены на двух сохранённых наборах символов настоящих PDF 17–18 и 18–19 ноября.
- Проверка SQL миграции 1 → 2 прошла на SQLite: новая таблица создана, старая запись каталога сохранена.
- Проверка хешей и структуры полного и частичного архивов выполняется при упаковке.

**Не подтверждено:** полноценная Android-сборка, Compose-компиляция и миграция на эмуляторе. Для этого нужен Gradle с Android SDK на твоём ПК.
