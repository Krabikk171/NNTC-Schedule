# NNTC Schedule 3.1.0-alpha.6 — уведомления выбранной группы

## Что меняется

- Фоновый Worker сравнивает старый и новый каталог **только для выбранной группы**.
- Если изменилось время, кабинет, предмет, преподаватель или состав пар на общей дате, Worker отправит уведомление о найденном изменении.
- Если к расписанию добавилась новая дата при наличии хотя бы одной общей даты со старой версией, это также считается обновлением.
- Исчезновение старой даты при сдвиге публикуемого окна PDF само по себе **не** считается отменой занятий.
- Не шлём уведомлений при первом заполнении каталога, если версии PDF не имеют общих дат, если есть дубли или если любая из двух проверяемых версий группы имела предупреждения распознавания.
- Если пользователь сменил группу во время фоновой проверки, перед отправкой уведомления выбранная группа проверяется повторно.
- Результат ручной проверки и статус WorkManager отображают изменения *выбранной группы*, а не контрольной `2РПУ-25-1`.
- Для контрольной группы оставлен привычный проверенный в 3.0 механизм уведомлений.
- Ошибка обновления каталога для другой выбранной группы теперь отображается как ошибка, не как успех.

## Что не трогали

`ScheduleTableParser.kt`, `ExperimentalGroupTableParser.kt`, `GroupCatalog.kt`, `ScheduleCsvCodec.kt`, `PdfParser.kt`, `PdfDownloader.kt`, `NotificationHelper.kt`, определения настроек профиля и визуальные темы.

## Что проверить на эмуляторе

1. Рекомендуется сохранить резервную копию текущей рабочей alpha.5.
2. Заменить файлы патча поверх исходников alpha.5 (или открыть полный проект).
3. Выполнить Gradle Sync и `:app:assembleDebug`.
4. Открыть приложение, выбрать другую группу (например, `2ТМ-25-1`) и нажать «Проверить обновления». При первом заполнении не должно быть уведомления.
5. Повторно проверить тот же PDF: если у выбранной группы ничего не изменилось — статус «без изменений», без уведомления.
6. При выходе нового PDF с **действительным изменением** в выбранной группе дождаться фонового Worker и проверить уведомление. Кнопка «Тест уведомления» проверяет только доставку уведомления, но **не** логику сравнения.
7. Выбрать контрольную `2РПУ-25-1` и убедиться, что её занятия сохранились.
8. Для групп с предупреждениями распознавания автоматические уведомления намеренно подавлены — требуется сверка по PDF.

## Ограничения

- На других группах пока применяется экспериментальный PDF-парсер. Отсутствие структурного предупреждения не доказывает абсолютную точность расписания.
- Фоновый Worker зависит от Android WorkManager и энергосбережения: точная периодичность не гарантируется.
- Отправка пользовательского уведомления выполняется Worker'ом; ручная проверка обновляет отображение и статус, но не вызывает уведомление непосредственно.
- Каталог всех групп всё ещё обновляется в том же цикле после успешного распознавания контрольной группы. В PDF, где отсутствует `2РПУ-25-1`, всеобщую синхронизацию надо будет доработать отдельно.
- Наличие уведомления требует системного разрешения и разрешённого канала уведомлений.

## Проверки в среде подготовки

- 11 из 11 локальных JVM-проверок чистой логики различий пройдены.
- Не выполнялась полноценная Android-сборка или проверка на эмуляторе; нужен `assembleDebug` на вашем ПК.
