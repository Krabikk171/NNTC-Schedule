# NNTC Schedule — экспериментальный UI «Слои» (кандидат для 4.0.0)

## Исходники и ограничения

Техническая база: `NNTCSchedule_3.1.0-alpha.8.3_source.zip` из папки `NNTC SCHEDULE/Источники`.
Из предыдущего дизайнерского UI отдельно восстановлена «Лента» (`NNTC_Lenta_alpha8.1.patch`) **с исправлением** `VisualEffects.kt` из `NNTC_Lenta_VisualEffects_fix_v1.zip`. «Маршрут» из alpha.8.3 сохранён.

Эта референсная копия НЕ содержит незагруженных исправлений пользователя и программиста после alpha.8.3 (например, дополнительные корректировки `ScheduleRouteUi.kt`). Не заменяйте ею живой проект целиком.

## Что добавлено

- `InterfaceStyle.LAYERS = "layers"`; сохранение через существующий SettingsRepository/DataStore.
- В существующем `ExperimentalDesigns.available` третий пункт «Слои»; не попадает в список обычных пяти стилей.
- `ScheduleLayersUi.kt` — независимый Compose-экран со светлой и тёмной темой, отдельными полупрозрачными подложками и контрастными передними карточками.
- Выбор дней/недель, подробности пар, режим с лентой/без ленты, номера пар, время, кабинет, преподаватель, поддержка `ParsedSubgroup` и ручная проверка обновлений.
- Расширение темы и фоновых цветов в `Theme.kt`/`VisualEffects.kt` без изменений «Маршрута».
- Регрессионные тесты `InterfaceStyleTest`, `ExperimentalDesignsTest`.

Никаких изменений в `MainActivity.kt`, `PdfParser`, `ScheduleParser`, Room, WorkManager, CSV, уведомлениях, репозитории, gradle/версии приложения.

## Файлы выпуска

1. `NNTC_Layers_UI_update_patch.zip` — хеш-проверяемое обновление `nntc-patch-v1`. Создано **тем же `tools/make_patch.py`**, который использует технический разработчик. База: alpha.8.3 **плюс «Лента» с исправлением VisualEffects**.
2. `NNTC_Layers_UI_git_diff.patch` — обзор точечных изменений от той же базы.
3. `NNTC_Layers_alpha8.3_with_ribbon_reference_source.zip` — полные исходники **только для сравнения и тестирования**, не заменять ими актуальный проект на компьютере.
4. `NNTC_Layers_interactive_preview.html`, PNG-снимки — визуальный прототип, не APK.

## Безопасная установка — путь программиста

1. Сохранить текущую рабочую копию (желательно Git commit).
2. Проверить, что в живом проекте уже присутствуют `InterfaceStyle.RIBBON` и исправленный `VisualEffects.kt`; техчасть желательно обновлена до alpha.8.3.
3. В корне проекта, где находится `app/build.gradle.kts`, выполнить:

```powershell
python tools/apply_patch.py --patch "C:\\путь\\NNTC_Layers_UI_update_patch.zip" --project "C:\\Android\\Projects\\NNTCSchedule"
```

4. Если обработчик напишет `CONFLICT: <путь> differs from patch base`, **не пытаться перезаписать файл**. Это означает, что у коллеги уже есть новые правки. Сравнить `NNTC_Layers_UI_git_diff.patch` и вручную перенести лишь добавления LAYERS в `InterfaceStyle.kt`, `ExperimentalDesigns.kt`, `ScheduleHomeUi.kt`, `Theme.kt`, `VisualEffects.kt` и два теста; добавить `ScheduleLayersUi.kt`. `ScheduleRouteUi.kt` оставлять рабочим и неизменным.
5. Собрать в Android Studio `:app:assembleDebug`, проверить логи компиляции и исправить их до установки.
6. На устройстве: «Настройки → 7 нажатий на версию → Разработка → Экспериментальные дизайны → Слои».

Ни один из трёх экспериментальных стилей не должен удалять базовые пять.

## Чек-лист приёмки

- Дизайн «Слои» активируется и корректно возвращается к «Маршруту» и «Ленте».
- Тёмная/светлая темы, без потери текста на стеклянных подложках.
- Включённая лента: выбор дня, предыдущая/следующая неделя, пустые даты.
- Выключенная лента: последовательный список нескольких дней.
- 1 / 3 / 7+ пар; длинные названия; крупный шрифт; два разных предмета в подгруппах.
- Нажатие на пару → корректные подробности; нижняя навигация → группа и настройки.
- Обновление использует старый `onRefresh`; нет новых запросов или записи в Room.
- Дополнительно проверить «Маршрут» (включая соединение линии с концом) и «Ленту» (включая устранённую ошибку VisualEffects).

## Что проверено в среде дизайнера

- На базе alpha.8.3 восстановлена «Лента» и исправлен нарушенный `when` в `VisualEffects.kt`.
- Самостоятельная компиляция Kotlin-каталога: **8 стилей, 3 экспериментальных** — успешно.
- Kotlin-проверка нового UI-файла: синтаксических диагностик нет, но зависимости Android/Compose недоступны (много ожидаемых unresolved-reference диагностик).
- HTML-прототип: открытие деталей, светлая/тёмная тема, переключение ленты дней, пустой день, настройки/группы — успешно.
- Применение хеш-патча к идентичной базе — проверяется при подготовке выпуска.

**APK и полная Gradle/Android-сборка не проверялись**: в этой среде нет Android SDK. После интеграции компиляцию обязан проверить технический разработчик.
