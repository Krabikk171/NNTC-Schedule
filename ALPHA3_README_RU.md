# NNTC Schedule — 3.0.0-alpha.3 (проверка на PDF 17–18.11.2026)

## Главное изменение

Теперь PDF парсится **по нескольким датам внутри одной страницы**, а продолжение
таблицы на следующей странице относится к предыдущей дате. Ранее ошибочно
предполагалось, что странице соответствует один день. Именно в приложенном PDF
на первой странице есть 17 ноября и начало 18 ноября, а на второй странице —
продолжение 18 ноября.

Выполнена проверка на **извлечённых текстовых элементах и их геометрии из
пользовательского PDF**: 2 дня, 6 пар группы 2РПУ-25-1 (по 3 в день),
все УП.04, кабинет 54, Федурин В.И.; 0 предупреждений. Проверена обратимость
CSV (PDF -> строки расписания -> CSV -> строки расписания).

Важно: это не полноценный запуск Android-сборки с PdfBox-Android на телефоне.
Разные библиотеки извлечения текста могут отдавать несколько отличающиеся
позиции. При проверке на устройстве нужен фактический результат.

## Новый формат хранения между парсером и базой

`ScheduleCsvCodec.kt` кодирует/декодирует CSV (UTF-8, кавычки RFC4180). В
`ScheduleRepository.kt` новый результат проходит через CSV до сохранения в
Room. Для диагностики последняя успешно разобранная таблица пишется в
`filesDir/last_schedule.csv` приложения. Это не отдельный скачиваемый CSV с
сайта: колледж по-прежнему публикует PDF; разбор PDF всё ещё использует
геометрию, но разрезает документ по датам и по ячейкам, а не склеивает строки.

## Установка

- Распакуйте архив в новый каталог; в Android Studio откройте вложенную папку
  `NNTCSchedule` (File -> Open).
- File -> Sync Project with Gradle Files; Build -> Make Project; установите app.
- Нажмите «Проверить обновления». Не очищайте данные приложения до проверки:
  старые записи защищены от ошибок распознавания.
- Если снова появится ошибка, пришлите её текст и лог `ScheduleTableParser`;
  для диагностики можно найти `last_schedule.csv` через Device Explorer.

Архив не включает `local.properties`, ключ подписи и файлы сборки.

## История предыдущей версии

# NNTC Schedule — 3.0.0-alpha.2

Исправленная версия исходного проекта. Цель — превращать PDF-таблицу расписания
в пары группы **2РПУ-25-1**: дата, номер пары, время, предмет, кабинет, преподаватель.

## Срочное исправление alpha.2 (после теста на телефоне)

На скриншоте от 17 ноября видно: загрузка PDF происходит, но приложение
пишет «Группа 2РПУ-25-1 не найдена», поэтому показывает оставшиеся в базе
записи за октябрь. Это **не новое расписание**.

- Ранее поиск группы работал только в зоне **левее самого левого времени**;
  случайная подпись времени могла исключить все названия групп из анализа.
  Теперь список групп ищется в левой части страницы независимо от времени.
- Когда в строке PDF переносится «2РПУ-25-» / «1», запись «8.10» из
  соседней колонки не должна распознаваться как группа «2РПУ-25-8».
  Различаем символы по расстоянию X и отдельно читаем перенос номера.
- При неудаче в Logcat по тегу `ScheduleTableParser` печатается количество
  обнаруженных групп и примеры названий, чтобы определить причину сбоя.
- Добавлены регрессионные тесты: неправильное положение заголовка времени,
  склеивание с временем, защита старых данных.

**Важно:** локально удалось проверить шесть сценариев на координатных
моделях, но байты актуального PDF из облака колледжа не удалось скачать в
тестовую среду. Исправление требует проверки на настоящем телефоне. Если
сообщение об ошибке повторится, понадобится сам PDF-файл или Logcat.

## Как установить поверх alpha.1

1. Закрой Android Studio и сделай резервную копию проекта, если вносил правки.
2. Распакуй архив и открой вложенную папку `NNTCSchedule`. Либо перенеси
   исправленные `v3/ScheduleTableParser.kt`, файл тестов, `Changelog.kt` и
   `app/build.gradle.kts` в свой проект, сохранив исходные пути.
3. Выполни Gradle Sync и `Build → Make Project`, затем установи новую сборку
   на телефон. **Не очищай данные приложения**, если хочешь сохранить настройки.
4. Нажми «Проверить обновления». При успешном разборе новый результат заменит
   старое октябрьское расписание в базе.

## Что изменено

- `v3/ScheduleTableParser.kt` — новый рабочий координатный парсер, используемый
  **напрямую** в `ScheduleRepository.updateSchedule()`. Старый Parser2 не участвует
  в заполнении базы данных; его исходник сохранён для справки.
- Колонки определяются по **началам времени** или по заголовкам `Время`,
  а не по надписям `1 пара` (они находятся над предметами).
- Границы строк вычисляются по названиям соседних групп. Поддерживается перенос
  `2РПУ-25-` + `1` на две строки, а также перенос половинок времени на разные строки.
- Для таблиц со специальной сеткой звонков поддерживается отдельный блок
  `ЗВОНКИ НА ДД.ММ.ГГГГ`.
- `PdfDownloader.kt` различает ответ PDF и ошибочный HTML/ответ сервера;
  пользователь получает причину ошибки, а не просто «Не удалось скачать PDF».
- При неудачном распознавании база **не перезаписывается**. Приложение
  продолжает показывать последнее сохранённое расписание.
- В `PdfParser.kt` включено подавление перекрывающихся дубликатов PDF-текста.
- В `app/src/test/.../ScheduleTableParserTest.kt` добавлены тесты на
  разделение 6 колонок, строку нужной группы и отдельную таблицу звонков.
- В alpha.2 `versionCode` поднят до `10`, версия — `3.0.0-alpha.2`.

## Как открыть и проверить

1. Распаковать архив. В Android Studio выбрать **Open** и указать папку `NNTCSchedule`.
2. Дождаться **Gradle Sync**. Если Android Studio предлагает установить
   Android SDK/Build Tools, установить их (проект использует compileSdk 37).
3. Запустить `app` в режиме Debug на телефоне или эмуляторе.
4. Нажать **«Проверить расписание»**. Если PDF доступен и соответствует структуре,
   приложение покажет пары нужной группы, сохранит их в Room и далее будет
   сравнивать обновления по существующему механизму.
5. Для тестов: `./gradlew :app:testDebugUnitTest` (Windows: `gradlew.bat :app:testDebugUnitTest`).
   Для диагностики: Logcat по тегам `ScheduleTableParser`, `PDF_DOWNLOADER`.

## Важно о проверке

Алгоритм и его ключевые ветки проверены JVM-тестами на координатных моделях,
включая таблицу с тремя занятиями `УП.04`, переносы времени, кабинет и
преподавателя, а также специальное расписание звонков. Исходный PDF колледжа
был просмотрен через веб-средство, но **его байты нельзя было получить в локальную
среду исполнения**, поэтому итоговая Android-сборка и запуск на реальном PDF
здесь не подтверждены. При другой разметке PDF может потребоваться уточнение.

Исходный архив пользователя остаётся неизменным. В выдаваемый архив **не включены**
личный `local.properties`, файл `release-key`, кэш `.gradle`, `.idea` и
скомпилированные файлы. Для последующего выпуска подписанной версии
нужен исходный ключ подписи пользователя (хранить отдельно от исходников).

## Формат результата в приложении

Например, по странице с тремя занятиями:

- `1 пара · 08:10–09:40 · УП.04 · кабинет 54 · Федурин В.И.`
- `2 пара · 10:00–11:30 · УП.04 · кабинет 54 · Федурин В.И.`
- `3 пара · 11:50–13:20 · УП.04 · кабинет 54 · Федурин В.И.`

Это **пример ожидаемого вывода**, а не утверждение о текущей успешной синхронизации на телефоне.
