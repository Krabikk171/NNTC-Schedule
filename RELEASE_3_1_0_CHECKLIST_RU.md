# NNTC Schedule 3.1.0 — перед публичной публикацией

**Пакет:** `ru.krabikk.nntcschedule`  
**Версия:** `3.1.0`, versionCode `35`  
**Разработчик:** Krabikk171  
**Тип архива:** исходники Android Studio, не APK.

## Обязательные проверки в Android Studio

1. Открыть чистую копию этого исходного проекта, выполнить Gradle Sync и `:app:assembleDebug`.
2. Выполнить `:app:testDebugUnitTest` и разобрать все ошибки, включая UI-тесты каталога 18 стилей.
3. Установить на устройство/эмулятор поверх совместимо подписанной версии; убедиться, что группа и настройки сохраняются. Не нажимать Clear Data.
4. Выбрать другую группу, проверить PDF-синхронизацию, пустой день, дни 19–21 ноября и два параллельных занятия с разными кабинетами.
5. Проверить отсутствие ложного уведомления при повторной загрузке того же PDF и появление уведомления при настоящем изменении.
6. Проверить 5 обычных оформлений и 18 экспериментальных (меню разработчика), обе темы, ленту дат включено/выключено, сегодняшнюю/прошлую/будущую дату, большие шрифты и скролл.
7. Особенно проверить «МАРШРУТ 1» и «МАРШРУТ 2» при выключенной ленте дат: прежняя ошибка Kotlin с `dayKey`/`clockMillis` не должна воспроизводиться.
8. Провести установку подписанного APK и проверить запуск. Для публичной раздачи создать свой **постоянный release-key**, не передавать его и не хранить в публичном GitHub. При смене debug-подписи на release-подпись приложение не сможет обновиться поверх debug APK обычным способом; перед удалением debug-версии сохранить нужные данные.

## Команды

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest
python tools/release_audit.py
```

Для подписанного APK: Android Studio → Build → Generate Signed App Bundle / APK → APK.  
Обязательно использовать один и тот же ключ в следующих версиях 3.1.1, 4.0.0 и далее.

## Перед публичной раздачей

- Проверить приложение на физическом Android, не только на эмуляторе.
- Подготовить описание, скриншоты и ссылку на GitHub Releases / Telegram-канал.
- Не публиковать `*.jks`, `*.keystore`, `local.properties`, `keystore.properties`, токены или личные данные пользователей.
- В приложении пока **нет** функции автоматической установки новых APK и кнопки донатов: они остаются в плане.
- Создать первый публичный релиз только после успешной сборки, тестов и подписи; до этого ZIP следует считать исходниками кандидата в релиз.
