# NNTC Schedule — как мы создаём и применяем патчи

## Главный принцип

**Один согласованный проект — одна основа для следующего изменения.** Мы не распаковываем файлы из двух параллельных чатов друг поверх друга наугад. Техническая ветка занимается PDF/CSV/Room/WorkManager/уведомлениями, дизайнерская — Compose/UI. Совпадение имён файлов не означает совместимость изменений.

## Из чего собирается патч

1. Фиксируется **исходный архив**, например `Projects 3.1.0-alpha2.zip` (до исправлений).
2. Создаётся новая рабочая копия с нужными изменениями и единым номером версии.
3. Различия определяются **по SHA-256 содержимого каждого файла**, а не по дате и названию.
4. В патч попадают только новые/изменённые файлы. В `NNTC_PATCH_MANIFEST.json` записаны пути, старые и новые хеши.
5. Скрипт применения сперва проверяет, что каждый заменяемый файл *действительно совпадает с той версией, для которой создан патч*. При несовпадении патч останавливается, чтобы не уничтожить работу второго чата.
6. Скрипт сохраняет резервные копии заменяемых файлов в `.nntc_patch_backups/`.
7. Полный проект собирается **отдельным ZIP** с корневой папкой `NNTCSchedule/`.

## Создание патча (из корня проекта или любой папки)

```powershell
python tools/make_patch.py --base "C:\\Backups\\NNTCSchedule_previous" --updated "C:\\Android\\Projects\\NNTCSchedule" --out "C:\\Backups\\nntc_patch.zip"
```

Вместо директории для `--base` можно передать архив предыдущей версии. Сценарий не поддерживает автоматические удаления исходников: если что-то нужно удалить, это надо явно согласовать.

## Применение без затирания чужих правок

```powershell
python tools/apply_patch.py --patch "C:\\Backups\\nntc_patch.zip" --project "C:\\Android\\Projects\\NNTCSchedule"
```

Если появилось `CONFLICT`, **не копировать патч принудительно**: оба чата могли поменять один Kotlin-файл. Нужен ручной трёхсторонний merge исходной версии, дизайнерской версии и технической версии.

Для текущего ZIP `alpha.8.1` патч изготовлен относительно пользовательского архива `Projects 3.1.0-alpha2.zip`. Если ты уже скопировал какие-то изменения после его отправки, безопасный скрипт может обнаружить конфликт. Тогда используй **отдельную распакованную копию полного проекта** и переноси свои дополнительные изменения только после сверки.

## Проверки до установки

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest
```

Проверяем: сборку, открытие «Маршрута», переход между группами, две подгруппы с разными преподавателями, обновление каталога без контрольной группы, миграцию Room из версии 1 в 2, отсутствие ложных уведомлений и сохранение пользовательского профиля.

## Что никогда не включать в архивы исходников

`release-key/`, `*.jks`, `*.keystore`, `*.p12`, `local.properties`, `.gradle/`, `.idea/`, `app/build/`, старые APK и персональные пути компьютера. **Релизный ключ должен оставаться только у владельца приложения**.

## Синхронизация двух чатов

Перед каждой работой берём последнюю **реально собранную и подтверждённую** версию, сравниваем общий набор изменённых файлов, при конфликтах вручную объединяем код. Никакого автоматического обмена локальными исходниками между чатами нет.
