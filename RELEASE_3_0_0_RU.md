## Проверка в Android Studio (Windows)

1. Сохранить резервную копию работающей версии и данных. Открыть папку проекта.
2. Выполнить `File → Sync Project with Gradle Files`.
3. Проверить `:app:testDebugUnitTest`, затем `:app:assembleDebug`.
4. Установить Debug APK на телефон с прежним ключом debug-подписи либо запустить через `Run`.
5. Убедиться, что в разделе «О приложении» показана версия `3.0.0`, а при первом запуске отображается полный changelog.
6. Проверить сохранённые занятия и все настройки оформления, переключатель ленты дней, ручную синхронизацию с сетью и без неё.
7. В меню разработчика снова получить отчёт и проверить, что количество пар/дней не изменилось без нового PDF.
8. Перед публикацией **создать подписанный Release APK/AAB** через Android Studio → Build → Generate Signed App Bundle or APK. Ключ хранить отдельно; не публиковать и не добавлять в исходники.
9. Для установки **поверх** опубликованной версии нужен совместимый ключ подписи и тот же `applicationId`; при несовместимой подписи Android не установит обновление.

## Почему в архиве нет «готового релизного APK»

Рабочая среда подготовки не содержит Android SDK и не может скачать инструменты Gradle, поэтому здесь невозможно подтвердить `assembleRelease`, подписать APK или тестировать его на реальном телефоне. Доступные исходники подготовлены для релиза, а не объявлены скомпилированным бинарником.

## Риски, которые надо учитывать

- Android WorkManager запускается с учётом системных ограничений и не гарантирует точный 15/30-минутный шаг.
- Реальное уведомление именно при изменении PDF желательно проверить на новом расписании колледжа.
- Поддержка PDF основана на структуре известного шаблона, поэтому новые варианты вёрстки могут потребовать правки парсера.
