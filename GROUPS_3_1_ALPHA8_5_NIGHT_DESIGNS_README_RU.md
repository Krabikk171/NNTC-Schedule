# NNTC Schedule 3.1.0-alpha.8.5 — шесть ночных дизайнов

**База для точечного патча:** `NNTCSchedule_3.1.0-alpha.8.4_MARSHRUT1_source.zip`.

Объединены пять присланных архивов дизайнера с шестью оформлениями:

| ID | Название | Главный компонент |
| --- | --- | --- |
| `layers_1` | Призма · СЛОИ 1 | `ScheduleLayers1Ui.kt` + `ScheduleExperimentalDayHost.kt` |
| `route_2` | Зелёная ветка · МАРШРУТ 2 | `ScheduleRoute2Ui.kt` |
| `focus_1` | Момент · ФОКУС 1 | `ScheduleFocus1Ui.kt` |
| `orbit_1` | Орбитальный поток · ОРБИТА 1 | `ui/orbit1/ScheduleOrbit1Ui.kt` + `ScheduleExperimentalDayHost.kt` |
| `layers_2` | Аквастекло · СЛОИ 2 | `ScheduleLayers2Ui.kt` + `ScheduleExperimentalDuoUi.kt` |
| `hologram_1` | Люмен · ГОЛОГРАММА 1 | `ScheduleHologram1Ui.kt` + `ScheduleExperimentalDuoUi.kt` |

Старый `route` («Маршрут») и `route_1` («Янтарная линия») сохранены. Всего **8 экспериментальных стилей** в меню разработчика; 5 обычных стилей не изменены. Перенос экспериментальных стилей в обычные настройки планируется только для 4.0.0.

## Что исправил интегратор

- `ScheduleFocus1Ui.kt`: дизайнер назвал главную функцию `ScheduleFocusUi`, а имя и диспетчер ожидали `ScheduleFocus1Ui`. Согласованы имена без переименования остальных функций.
- «Призма» и «Орбита» в исходных архивах были только независимыми UI-модулями. Добавлен `ScheduleExperimentalDayHost.kt` с реальными датами, обновлением, настройками, выбором группы и подробностями занятий, а также `ExperimentalUiAdapters.kt` для отдельных подгрупп и временных интервалов.
- Для `java.time` (ОРБИТА 1) включён **core library desugaring**: минимальная Android-версия остаётся 24, а `java.time` работает также на Android 7.x.
- Все новые стили зарегистрированы в `InterfaceStyle`, `ExperimentalDesigns`, диспетчере `ScheduleHomeUi` и теме Material. Это добавочные изменения, не замена старых стилей.
- Для всех новых `ModalBottomSheet` проверен явный `@OptIn(ExperimentalMaterial3Api::class)`.

## Сохранность технического ядра

Не менялись `PdfParser.kt`, `ScheduleRepository.kt`, `ScheduleUpdateWorker.kt`, Room-сущности/DAO/миграции, `ScheduleCsvCodec.kt` и парсеры каталога в `v3/`. Поменяны только файлы UI, тесты, документация, версия, конфигурация desugaring.

## Ограничения

1. **Android SDK и Gradle-сборка `:app:assembleDebug` в рабочем окружении недоступны**. Кандидат требует сборки и проверки на эмуляторе, прежде чем объявлять beta.
2. Эти пять ZIP не содержат исходников прежних экспериментальных «Ленты» и исходных «Слоёв». Исходная техническая база alpha.8.4 их тоже не содержит. **Не распаковывайте полный ZIP поверх живой ветки дизайнера**, если эти стили уже присутствуют. SHA-проверяющий патч остановится при конфликте, что безопаснее.
3. В СЛОИ 1 и ОРБИТА 1 без горизонтальной ленты используется переключение между сохранёнными датами стрелками (вместо полного многодневного списка). Это осознанный безопасный вариант без вложенных вертикальных прокруток.
4. Экспериментальные стили намеренно допускают изменения UI до 4.0.0; не публиковать как проверенную сборку без тестов.

## Применение патча без потери дизайнерских изменений

1. Создать резервную копию папки проекта или Git commit.
2. Для **точной** базы alpha.8.4 из корня приложения:

```bash
python tools/apply_patch.py --patch /путь/NNTCSchedule_3.1.0-alpha.8.5_night_designs_patch.zip --project .
```

Если выдаст `CONFLICT`, **не** распаковывайте файлы поверх: в проекте уже есть другие правки, и требуется слияние исходников.

3. В Android Studio выполнить Gradle Sync и `:app:assembleDebug`.
4. На эмуляторе проверить все восемь экспериментальных стилей, светлую/тёмную тему, выбор другой группы, дни 0/1/6+ пар, параллельные подгруппы, обе настройки ленты, нажатия на занятия, обновления и фоновые уведомления.
5. Не очищать данные приложения: миграции базы не менялись.
